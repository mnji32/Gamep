# ☕ 카페 생존일지 : 알바생의 하루

> HTML **머지(Merge) 게임 원본 코드**를 분석하고, 문제점을 고치면서 **프롬프트 30개**로 업그레이드한 웹 게임 프로젝트

## 🎮 게임 소개

카페 알바생이 되어 재료를 합쳐 메뉴를 만들고, 제한 시간 안에 손님 주문을 처리하는 **머지 · 카페 경영 게임**

| | 원본 | **최종** |
|---|---|---|
| 코드 | 135줄 | **1,974줄 (HTML 파일 1개)** |
| 아이템 | Lv.1 ~ Lv.N 숫자 블록 | **4종류 × 5단계, 메뉴 20개** |
| 조작 | 드래그 앤 드롭 | **터치(클릭) 두 번** |
| 목표 | 합칠 때마다 점수 획득 | **3라운드 · 손님 서빙 · 하트 3개** |
| 결과 | 점수만 표시 | **등급(F ~ S+) 결과창 · 순위 · 최고 기록** |
| 연출 | 없음 | **도트 그래픽 · BGM · 효과음 · 직접 만든 캐릭터 13종** |

## ▶ 실행 방법

설치 없이 `index.html`을 브라우저(Chrome 권장)로 열면 바로 실행돼요. PC와 모바일 모두 지원

## 🕹 조작법 & 규칙

| 조작 | 동작 |
|---|---|
| 아이템 터치 → 같은 아이템 터치 | 합치기 (다음 단계 메뉴) |
| 아이템 터치 → 빈칸 터치 | 이동 |
| 메뉴 터치 → 손님 터치 | 서빙 |
| `재료 상자` / `휴지통` | 빈칸에 재료 추가 / 선택한 아이템 버리기 |
| `ESC` / `일시정지` 버튼 | 일시정지 (계속하기 · 재시작하기 · 그만하기) |

- **메뉴 트리:** 같은 아이템 2개 = 다음 단계. **3단계부터** 손님에게 팔 수 있어요.

  | 종류 | 1단계 → 5단계 |
  |---|---|
  | 커피 | 커피 원두 → 에스프레소 → **아메리카노** → **카페라떼** → **아인슈페너** |
  | 녹차 | 녹차 잎 → 찻잎 우림 → **녹차** → **녹차 라떼** → **녹차 프라페** |
  | 복숭아 | 복숭아 → 복숭아청 → **아이스티** → **스무디** → **버블티** |
  | 디저트 | 밀가루 → 빵 반죽 → **소금빵** → **와플** → **조각 케이크** |

- **라운드:** 라운드마다 3분 안에 목표 손님 수를 채우면 통과

  | 라운드 | 목표 손님 | 보드 | 손님 대기 시간 |
  |---|---|---|---|
  | 1 | 7명 | 6×6 | 90초 |
  | 2 | 10명 | 6×6 | 100초 |
  | 3 | 12명 | 7×7 | 110초 |

- **하트:** 3개. 대기 시간이 끝나 손님이 화나서 나가면 1개 감소, 모두 잃으면 게임 오버
- **점수:** 3단계 30점 · 4단계 70점 · 5단계 150점 + **빠른 서빙 보너스** `기본 점수 × 0.5 × 남은 대기 시간 비율`
- **등급:** S 3라운드 통과 · A 3라운드 실패 · B 2라운드 실패 · C/D 1라운드 실패 · F 그만하기
  (점수가 높으면 **S+ 3,200↑ · A+ 3,050↑ · B+ 1,430↑**)
- **부가 요소:** 손님 카드 수집 · 실시간 보너스 미션 · 레시피북(보는 동안 시간 정지)

## 🐞 원본 코드의 문제점

첫 프롬프트에서 코드를 바로 고치지 않고 **분석만** 시켜 `버그 / 구조 / 사용성` 표로 정리

**버그**
1. 드래그 상태가 초기화되지 않음
2. 레벨 상한이 없음 → 끝없이 합쳐짐
3. drop 처리 누락

**그 밖의 문제**
- **구조:** 전역 변수 남용, 숫자 하드코딩
- **사용성:** `alert` 창으로 알림, 모바일 터치 불가

## 💡 프롬프트 작성 방식

- **역할 부여:** "너는 30년차 베테랑 게임 개발자야"처럼 역할을 정해 주고 원본 게임을 만들게 함
- **분석 먼저:** 코드를 바로 고치지 않고 문제점부터 표로 정리 → 버그만 먼저 수정 → 리팩토링 순서로 진행
- **이유 설명:** 수정할 때마다 왜 그렇게 고쳤는지 한 줄씩 설명하게 함
- **계산 근거 밸런스:** 메뉴 단계별 합치기 횟수(3번 / 7번 / 15번)와 3분 동안 받을 수 있는 손님 수를 먼저 계산하고, 그 결과로 수치를 정하게 함
